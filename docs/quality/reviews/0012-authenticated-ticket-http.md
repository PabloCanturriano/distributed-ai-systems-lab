# Authenticated ticket submission over HTTP

Status: implementation prepared for exact-patch review, not committed or pushed. Base `10ed63f` was pushed with owner authorization. This slice connects the accepted submission contract to real credentials, Redis request admission and the existing atomic PostgreSQL operation. No dependencies, schema or Compose service settings change.

Proposed commit: `feat: expose authenticated ticket submission with request limits`.

## Patch and behavior

- `apps/api/src/ticket-http.ts`, `app.ts`, `main.ts`: Nest POST controller, explicit bounded JSON input and service injection (with the persistence-boundary comment updated to match the new wiring). Returns 202 with the stable receipt, Location, fresh server request UUID and no-store headers. Errors have the agreed generic body; 401 includes a Bearer challenge, 429/503 have finite Retry-After. Other routes do not gain an authentication bypass.
- `apps/api/src/ticket-access.ts`: accepts opaque `Bearer <lookupUUID>.<canonical-base64url-secret>`. SHA-256 matches the seed protocol; digest comparison uses `timingSafeEqual`, including a dummy digest for missing lookup IDs. A read-only transaction resolves non-revoked/non-expired credentials and active principal membership without caching. Tenant and role come only from PostgreSQL; readers cannot submit. SQL/private errors map to generic dependency failures.
- `apps/api/src/submission-limits.ts`, `dependencies.ts`: bounded Lua checks/increments use Redis TIME and fixed UTC minute windows. Limits are 300 per actual peer address, 120 per principal and 10 submissions per tenant. Principal/tenant checks occur together before their counters increment; rejected limit checks do not increment those two counters. Ingress still counts attempts. Admitted retries/invalid bodies consume request allowance. Counter TTL is 120 seconds. The client queue is bounded at 64 pending/in-flight commands; the former readiness-only limit of eight could reject the declared concurrent business burst before quota evaluation. Corrupt numeric state, Redis failures, offline/overflow queues or command deadlines fail closed. Readiness and limiter operations share a complete 1-second Redis command deadline; timed-out connections close without client replay. A timed-out command might already have consumed allowance; no business write is accepted on that error.
- `tests/ticket-http.test.cjs`, `tests/database/ticket-submission.test.cjs`: transport contracts and real PostgreSQL credential-state tests. `scripts/compose-smoke.mjs`, `scripts/ticket-http-scenario.mjs`: real API/PostgreSQL/Redis checks with generated credentials, concurrent limits, revocation and dependency failures. The scenario script is a trusted host test helper injected into a temporary seed job, excluded from application images. It does not print credentials or expose fault injection as a route.
- README, documentation map, contract/data-model/test statuses, local identities, security and roadmap receive short current-scope updates; this report records evidence.

JSON bodies are limited to 16 KiB, including chunked input, with a 3-second body-read deadline after admission checks. Only UTF-8 application/json and identity encoding are accepted. Malformed UTF-8/JSON, duplicate authorization/idempotency headers and invalid submission schemas fail before business mutation. Ingress uses the socket peer, ignoring forwarded headers. Body bytes are read outside SQL transactions; SQL uses the existing bounded pool and scoped roles. No raw demo credentials are mounted into API; its one read-only database-password mount is unchanged. Standalone dependency-disabled mode rejects POST with 503.

## Remaining scope

This implements submission-level HTTP-01/02/03/08 and selected SEC-01/02/04/08/09/10 checks in the cases above, not every scenario family. Rate limits are local fixed-minute abuse controls; boundary bursts and resets after disposable Redis restart remain limitations. Tests coordinate Redis-time windows and modify only their own installation's counters between independent cases.

The receipt's statusUrl names the agreed GET route, which is **not implemented yet**. Reads, replay, CLI credential assembly, OpenAPI generation, Kafka publication/consumption, durable jobs, AI results and telemetry remain later slices. Tickets stay queued with pending outbox rows. Credential changes affect subsequent authentication; this does not promise cancellation of already admitted requests/jobs. This is trusted local infrastructure with fictional data, not a production identity or availability guarantee.
