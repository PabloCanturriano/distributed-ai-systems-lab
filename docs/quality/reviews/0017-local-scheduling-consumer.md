# Native local scheduling consumer

Status: prepared under owner-approved ADR-0007, pending exact-patch commit review. Base `5acb67d` and its preceding four commits were pushed to main with owner authorization. Proposed commit: `feat: consume Kafka events into durable scheduling jobs`.

## Purpose and affected files

The opt-in local path now connects authenticated HTTP submission, the outbox relay, real Kafka consumption and atomic SQL job admission. A callback commits only its explicit next offset after SQL admission/quarantine resolves. The default worker remains idle, API readiness retains its PostgreSQL/Redis boundary, and execution state remains queued.

- `apps/worker/src/kafka-scheduling-consumer.ts`: isolated native adapter using the existing pinned Confluent SDK 1.11.0. Automatic commits/topic creation are disabled; group `lab-ticket-scheduler-v1` subscribes only to scheduling requests. SDK and application serialization permit one callback at a time. SQL failures retain the callback with an interruptible 500 ms retry delay; queued callbacks cannot skip it. A failed/ambiguous broker commit has a five-second complete response bound and stops consumption. Unsafe current/next offsets fail before admission because the pinned SDK uses Number internally.
- The SDK manages offset storage and rejects a supplied `enable.auto.offset.store`; the adapter does not supply it. Its `stop()` is unimplemented. Lifecycle cancellation therefore uses `disconnect()` outside the message callback, with an owner callback arming the process deadline before teardown even on startup/commit failure. Late commit responses cannot resume the stopped callback queue. Native diagnostics are suppressed; application events contain only fixed statuses.
- `apps/worker/src/consumer-main.ts`: separate local entry point, strict owned/mode/size/canonical password-file checks, `lab_worker_login`, bounded pool/query/connection settings, fixed safe logs, signals and a 12-second hard shutdown deadline. No bootstrap/migration privilege or raw demo credential is used.
- `packages/configuration/src/index.ts`, `tests/configuration.test.cjs`: separately validated local consumer endpoints and safe errors. `infra/docker/Dockerfile`, `compose.yaml`: consumer target inherits the already verified native artifact stage; opt-in non-root/read-only/capability-free container, backend only, worker-secret-only read-only mount, no ports/socket, seed/topic startup gates and a 256 MiB chosen limit. Default image paths and native artifact pins do not change.
- `tests/kafka-scheduling-consumer.test.cjs`: acknowledgement ordering, serialization through SQL failure, offset precision guards, ambiguous/hung commit stop, late response, cancellation and pre-aborted startup. `scripts/consumer-smoke.mjs`, `scripts/consumer-test-actor.mjs`, `package.json`: real broker/database acceptance and injected test-only checkpoint/producer actors. The Docker allowlist excludes these scripts; production has no public/environment fault hook.
- `.github/workflows/foundation.yml`: consumer gate on x64 and arm64 jobs, with adjusted finite deadlines. README/map/roadmap, ADR status and operation notes identify implemented versus remaining behavior. No dependency, lockfile, SQL schema or privilege changes.

## Actual verification on 2026-11-20

Red: the first acknowledgement-ordering test suite failed because the consumer adapter module was absent. After implementation:

- `npm run check`: formatting, types/builds and **127 fast tests in 10 suites** passed. Tests verify no commit before SQL resolves, no later callback bypass during failed admission, safe current/next offsets, stop after broker rejection or a five-second no-response deadline, no resumption after late acceptance, and unacknowledged SQL work during shutdown.
- `CONSUMER_TEST_PLATFORM=linux/amd64 npm run test:consumer` passed. Authenticated HTTP -> actual relay -> native consumer -> one SQL job was independently checked in PostgreSQL. Real repeated event IDs and distinct valid IDs for one generation retained one job; Kafka's JVM group tooling observed the explicit next offsets.
- Invalid raw input entered metadata-only quarantine with its exact source offset/digest before group advancement. Stopping PostgreSQL kept an earlier callback pending; a later record was published into the same partition, and independent broker inspection showed no advance past the earlier delivery. Shutdown while SQL was unavailable exited successfully within 15 seconds without acknowledging it. Restart recovered both jobs in order.
- A test actor awaited after a real admission COMMIT but before broker commit. A second real group member caused a broker-observed rebalance. The host then killed the held container with SIGKILL, and the new owner redelivered/committed without replacing the original job or inbox identity. Production carries no checkpoint flag.
- The adapter/SQL handoff executed on Linux **arm64** and **amd64 under Docker Desktop emulation**, using librdkafka **2.16.0**. The alternate client consumed an HTTP-created event, persisted its job and committed a broker-inspected offset. This is not physical amd64 hardware evidence or an all-amd64 dependency stack.
- Missing credentials failed with only fixed events. Inspection verified the consumer's non-root/read-only/no-capability runtime, no host ports and only its read-only worker-secret mount. Captured logs were checked against payload/question fixtures and known credentials inside trusted jobs without exporting credential values. All executions remained queued.
- An initial outage-test attempt used Compose start, which restarted PostgreSQL as a dependency and invalidated the intended outage checkpoint. The corrected harness starts only the existing consumer container through Docker; the corrected full outage/rebalance/cross-architecture run passed. This was a diagnosed harness issue, not a quarantined flaky scenario.

`npm run test:compose` passed the default startup/idle-worker path, real authenticated HTTP/idempotency/rate limits/reads, PostgreSQL/Redis stop/pause recovery, persisted credentials/rows and missing-secret gates. Final formatting, workflow lint with actionlint 1.7.12, relative documentation links and whitespace checks passed. No SQL protocol changes were made; the base's 113 PostgreSQL tests were not rerun locally for this adapter patch. The [pushed base workflow](https://github.com/PabloCanturriano/distributed-ai-systems-lab/actions/runs/44804399372) completed successfully for `5acb67d05e884cfdd1da02b57d0d95f0bbb3effc`; this does not establish hosted CI success for the new uncommitted consumer gate.

## Provenance and limits

Registry metadata still identifies SDK **1.11.0** with the same pinned integrity; no candidate/dependency version changed. The scoped API/worker production npm audit reports **0 findings**. Existing arm64/x64 Node-ABI-137 artifact checksums, disabled npm hooks and license/notice retention are reused. Native/OS SBOM and vulnerability-scanning gaps remain open release gates; npm audit is not a native/OS scan.

Environment: Node **24.22.3**, Docker Desktop **29.2.1**, PostgreSQL **17.12**/pgvector **0.8.7**, Kafka **4.4.0**. No throughput, minimum-hardware, high-availability or production-security claim is made.

A failed startup/ambiguous offset commit stops the service and needs an operator restart; no automatic restart policy is introduced. A shutdown deadline may force exit with uncertain SQL/broker acceptance, leaving recovery to redelivery. This patch implements admission, not execution: no executor, attempts/results, AI calls, replay or exactly-once effects. The complete ticket-to-answer workflow remains unfinished.
