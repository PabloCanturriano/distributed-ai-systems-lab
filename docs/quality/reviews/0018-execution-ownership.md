# Durable execution ownership and failure recovery

Status: prepared for exact-patch review under the accepted ADR-0001 SQL execution architecture. Not committed or pushed. Base `df155ba` contains the approved native scheduling consumer and is pushed. Proposed commit: `feat: add leased execution ownership and failure recovery`.

## Purpose and affected files

This slice gives consumer-created jobs a durable attempt owner. Claims and renewals use database time; stale/expired tokens cannot retry or finalize a replacement owner. Every claim consumes the stored budget, including crashed attempts. Retry exhaustion or permanent failure atomically closes the job/execution and creates one sanitized failure notification. No executor polling loop, external model/tool call, completion/result persistence or public failure DTO is activated.

- `database/migrations/1795305600000_execution-ownership.cjs`: extend queued-only jobs to queued/running/failed, paired lease and failure fields, immutable attempt identities/numbers with outcome constraints, a composite current-attempt FK and targeted queued/expired indexes. A partial unique index permits at most one terminal failure notification per execution without restricting distinct scheduling/repair identities. Destructive rollback is refused; no attempt is synthesized for an existing queued job.
- Worker grants now permit execution status updates, ownership metadata, attempt insertion/outcome updates and outbox content insertion. This is the existing shared worker role used by consumer/executor modules, not separate component credentials. Ticket messages/credentials, job source identities, stored attempt budgets, attempt identities/numbers and outbox payload reads remain denied. The admission privilege test changes its immutable-column assertion accordingly; it no longer claims attempt counters are immutable to the worker.
- `apps/worker/src/execution-ownership.ts`: one-job claim using ticket SKIP LOCKED, then consistent ticket -> execution -> job locking and fresh eligibility checks. The method never scans queued executions as a substitute for consumer-created jobs. A claim records a new attempt token, consumes one budget unit, assigns a 30-second lease and changes the execution to processing in one transaction. Reclamation closes the expired attempt before assigning a new owner.
- Renewal/retry/failure lock the same rows before checking generation, processing/running state, token and current database time. Live renewal preserves token/budget; expired ownership cannot be resurrected. Retry marks the attempt retryable and returns job/execution to queued with database-time full jitter bounded by min(10 seconds, 1 second * 2^(attempt-1)). The default three-attempt budget is retained. Exhausted recovery creates no fourth attempt.
- Permanent/exhausted failure stores only EXECUTION_FAILED/ATTEMPTS_EXHAUSTED, clears ownership, updates the execution and inserts the immutable failure event/digest atomically. Correlation comes from the execution and causation from the event actually admitted by the job. Repeated finalization or lost commit acknowledgement cannot create another logical terminal event. SQL/connection errors are generic and uncertain connections are discarded; callers still own bounded pool/network settings.
- `tests/database/execution-ownership.test.cjs`, `tests/execution-ownership.test.cjs`: independent real-PostgreSQL fixture with authenticated NOINHERIT API/worker logins, concurrency/locks/expiry/budgets/rollback/ambiguous commits/privileges, plus pre-SQL identity and safe error checks. Other database fixtures explicitly include attempts in cleanup.
- `tests/database/foundation.test.cjs`: seven-migration history and seeded 2/3/4/5/6-migration upgrades. The six-migration fixture admits a real queued job before upgrade and verifies its existing fields are retained, new lease/failure fields are null and no historical attempts are invented.
- `scripts/consumer-smoke.mjs`: trusted operator invokes this adapter on an actual HTTP/Kafka-consumer-created job, then independently reads its terminal record from the real failure topic. The expected lifecycle assertion now distinguishes that intentional failure from still-queued jobs. No runtime test flag or public mutation route is introduced.
- Focused README/map/roadmap/data-model/operation and prior-slice status updates. No dependencies, native client configuration, Compose service or public API changes.

## Actual verification on 2026-11-20

Red: after PostgreSQL setup and actual admission succeeded, the first claim test failed because the ownership module did not exist. After implementation:

- `npm run check`: formatting, types/builds and **131 fast tests in 11 suites** passed.
- `npm run test:database`: **134 real PostgreSQL tests in 3 suites** passed. Claims commit attempt/job/processing state together; injected claim-write failure leaves none of those changes. Eight simultaneous claimers produce one owner/attempt. A held ticket is skipped while another eligible job can be claimed. Unadmitted queued tickets and unscheduled new generations cannot be claimed.
- Live renewal extends the lease without resetting budget or token. Expired recovery retains the old expired attempt and assigns a new token. For renew/retry/fail, a ticket is held unchanged through a short fixture lease expiry; pg_stat_activity proves blocking and database time proves expiry before release. Every pending operation then rejects ownership. Old tokens and manually advanced generation fixtures cannot mutate a newer owner/generation. Fixture timestamp/pointer changes are not implemented operator repair or a replay API.
- Retry eligibility stays within its declared jitter bound and is honored by later claims. Three transient retries and three expired/crashed attempts both exhaust at three, store ATTEMPTS_EXHAUSTED and create no fourth attempt. Permanent failure preserves the admitted event as causation even when it differs from the original scheduling event.
- Failure-outbox INSERT rejection rolls back attempt/job/execution changes. Real server commits followed by simulated lost terminal/claim acknowledgements retain committed state without another failure identity or immediate extra claim. The terminal uniqueness index rejects another failure identity. Composite FKs reject another job's attempt token; outcome constraints reject a terminal attempt with no safe code. Runtime privilege tests retain the denied content/identity/budget boundaries.
- `npm run test:consumer` passed on Linux arm64 with the seventh migration. An actual HTTP-created event traversed the relay and native consumer into a job; the trusted ownership probe claimed/failed it and the real relay published the exact key/payload to `tickets.execution-failed.v1`. The failure did not create another job. Existing broker offsets, duplicate identities, quarantine, PostgreSQL outage/recovery, shutdown, SQL-before-offset crash and rebalance checks also passed.

`npm run test:compose` passed with the seventh migration: default API/idle-worker startup, real authenticated HTTP/idempotency/rate limits/reads, PostgreSQL/Redis stop/pause recovery, credential/data persistence and missing-secret gates. Final formatting, relative documentation links and whitespace checks passed. ## Limits and next implementation

The SQL protocol runs in tests/operator probes, not a background executor service. Processing/failure writes are fenced; successful result writes do not exist yet and must not rely on a separate earlier ownership read. The future completion transaction must lock/check/write together. Public GET still supports queued/processing only and fails closed for unsupported terminal representation. No model quality, external-call deduplication, complete ticket-to-answer workflow, throughput or release is established here.

The future executor owns the five-second heartbeat cadence and monotonic 60-second total attempt deadline; this module implements the 30-second database lease, not a running heartbeat/timer loop. External calls must stay outside SQL transactions. The existing role boundary trusts worker code; it is not tenant RLS or a sandbox for a compromised worker credential. Native/OS inventory/scanning gates remain unchanged; no new audit/security-clean claim is made.
