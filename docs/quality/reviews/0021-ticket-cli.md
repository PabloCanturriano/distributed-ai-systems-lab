# Containerized ticket CLI with bounded HTTP retries

Status: approved, committed and pushed as `2f69c99` (`feat: add a Docker ticket CLI with bounded HTTP retries`). Its [hosted workflow passed](https://github.com/PabloCanturriano/distributed-ai-systems-lab/actions/runs/45478107145), including the CLI gate on x64 and ARM64. The evidence below records that slice at implementation time; [review 0022](0022-ticket-replay-batch.md) adds replay.

## Purpose and affected files

A reviewer can submit, inspect and wait for tickets without writing HTTP requests or retrieving bearer credentials manually. This implements the first CLI slice of accepted ADR-0002/0004 and the reviewed CLI/security contracts. It introduces no new application service, scheduling shortcut, database role, migration or runtime fault interface.

- `apps/cli/package.json`, `apps/cli/tsconfig.json`, `apps/cli/src/cli.ts`: strict TypeScript workspace and Commander parser for `demo`, `ticket create/get/wait`, explicit identity, 1–300-second overall deadlines, JSON/no-color/help. Invalid/duplicate switches fail before credential/network access. UUID arguments normalize to lowercase. Responses are bounded to 32 KiB, validated and projected onto supported fields; raw upstream messages and unknown fields are omitted. The API remains authoritative for roles, tenants, idempotency and limits.
- The client uses the fixed trusted Compose endpoint, manual redirect handling, five-second per-attempt limits and one-second polling. Transport/503 operations retry at most twice with the same generated/supplied key and normalized body. This includes response-body loss after headers. Supported Retry-After delays up to five seconds are honored; longer values decline retry rather than retrying too soon. Wait/demo distinguish durable failure, transport/contract errors and deadline expiry; create distinguishes acceptance from completion. Request IDs, keys and the last validated ticket remain available where safe.
- `apps/cli/src/credentials.ts`, `apps/cli/src/main.ts`: private read-only manifest selection, owned private directory/file checks, no-follow leaf open, bounded manifest and distinct aliases/lookup IDs/canonical secrets; cancellation on process signals; one final JSON stdout envelope with fixed progress on stderr. Default output is indented JSON; `--json` is compact. No question or raw credential is printed.
- `package.json`, `package-lock.json`: build/typecheck integration and `test:cli`; only one new external package, exactly pinned Commander 14.0.3. The [official release](https://github.com/tj/commander.js/releases/tag/v14.0.3) is the maintained CommonJS-compatible line used with the existing Jest setup. [Commander 15 release notes](https://github.com/tj/commander.js/releases/tag/v15.0.0) explain its ESM-only migration and Commander 14 security maintenance through May 2027. This is a compatibility choice, not a claim that 14 is the newest major. Installation used lifecycle scripts disabled; no vulnerability-free claim is made.
- `.dockerignore`, `infra/docker/Dockerfile`, `compose.yaml`: allowlisted CLI sources, separate scoped dependency/runtime target, optional on-demand `tools` service with API-health dependency. The CLI has only the read-only demo volume, backend network, no host ports/socket, a non-root user, read-only root and all capabilities dropped. PostgreSQL/native Kafka clients are absent from its runtime image. Existing default Dockerfile target and default-profile worker behavior are retained.
- `tests/cli.test.cjs`, `tests/cli-credentials.test.cjs`, `tests/cli-transport.test.cjs`: 61 client/credential/transport cases, including real loopback redirect refusal, partial-response POST retry and stalled-body cancellation.
- `scripts/cli-smoke.mjs`: a full image-built HTTP → relay → real Kafka → consumer → executor → persisted HTTP result journey in a unique empty-volume project; the CLI calls no internal persistence/scheduling module. All fixture mutations are ordinary submissions or scoped lifecycle operations. Cleanup removes only the owned project.
- `.github/workflows/foundation.yml`: `test:cli` follows `test:executor` on x64 and ARM64; existing job budgets/permissions remain unchanged.
- README, map, roadmap, CLI/security/identity/test/CI operation notes and review 0020: executable subset, commands, output/exit semantics, baseline status and evidence limits.

## Actual verification on 2026-11-23

Red: the initial creation/retry test failed because the CLI implementation module did not exist. After implementation, its lost-acknowledgement assertion passed with an unchanged key and payload. An initial invalid-arguments test table accidentally spread argument arrays into the Jest callback (including its done parameter); the fixture was corrected, rather than increasing its timeout. A later full check caught a credential-test formatting issue; formatting was corrected before the final check.

- `npm run check`: formatting, type checks/builds and **222 tests in 15 suites** passed. The new tests cover invalid arguments before credential reads, retained submission keys, bounded transport/503 retries, no conflict/auth/rate-limit retry, deadline/failure exits, safe projections, credential failures and cancellation. The three real HTTP tests use ephemeral loopback listeners and close their own connections/listeners; the stalled response is actually aborted at the overall deadline.
- `npm run test:cli`: passed from empty volumes with the final application revision. Real create/get/wait/demo commands produced parseable single-object JSON with explicitly simulated abstention and empty citations/tools. Duplicate submissions retained their receipt; conflicting input returned 409/exit 2, readers could read but not submit (exit 3), foreign and absent tickets returned the same 404 code, and waiting on a queued ticket expired with exit 5. Restarting the executor completed that durable ticket; demo completed another tenant's ticket. Missing credentials failed closed, a stopped API produced transport exit 4, and image/mount inspection plus in-container comparison confirmed no raw credential in captured output/logs. The documented normal dependency-starting demo invocation is also exercised by the final smoke script.
- `npm run test:containers`: existing API/worker startup, isolation, safe configuration rejection and shutdown passed after the Dockerfile/workspace changes.
- `npm run test:compose`: the default-profile regression passed: authenticated HTTP/idempotency/limits, readiness degradation and recovery during Redis/PostgreSQL stop/pause without an API restart, clean shutdown, preserved rows/credentials after recreation and missing-secret startup gates.
- `actionlint` 1.7.12 reported no errors for the changed workflow. Final syntax, formatting, relative Markdown links and whitespace checks passed.

Environment: Node 24.22.3; Docker Desktop engine 29.2.1/Linux arm64; Compose 5.1.0; PostgreSQL 17.12/pgvector 0.8.7; Kafka 4.4.0. Docker suites run sequentially in isolated owned projects. This new CLI patch has not run in hosted CI or local x64. The separate database/relay/consumer/executor suites were not rerun independently because their application code, schema and native pins did not change; the CLI journey exercises those real components, while image/default Compose regressions cover the affected packaging boundaries.

## Limits and approval boundary

The result remains a fixed simulated abstention: no retrieval, cited answers, tools, replay, scenarios, evaluation harness, real model, throughput claim or release is added. Default stack startup still needs both messaging/execution profiles for autonomous completion. Help lists the supported subset; unsupported commands fail rather than implying success. Trace request IDs are available, but this slice does not implement distributed telemetry.

The endpoint is intentionally fixed to the trusted local API; remote opt-in/HTTPS configuration is deferred. Manifest digest format is checked, while seed/database consistency remains the trusted initializer's responsibility. The CLI may read all six fictional local credentials from its private volume; it is not a production secret store or a network firewall. Ancestor paths/host operator remain trusted. The configured 128 MiB memory limit is not a measured minimum. Client cancellation/deadline does not cancel durable work or prove that a timed-out POST was not accepted; the retained key enables safe deliberate retry. Crash-after-acceptance before stdout can still require a user-supplied stable key for cross-process recovery.
