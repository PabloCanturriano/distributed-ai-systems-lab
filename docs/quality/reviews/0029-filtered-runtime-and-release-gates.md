## Runtime refinement

[ADR-0009](../../adr/0009-filtered-node-runtime.md) retains the existing official Node 24.22.3 bookworm digest and established role/privilege/network boundaries. The exporter accepts only inspected system-library paths and reviewed package owners, retains four actual Debian package records, records hashes of copied files and preserves the original common-license texts referenced by Debian copyright files. Each final role has a matching runtime ledger and corresponding-source identities. Shell, package installers, Corepack and unrelated OS utilities are excluded from every final layer. The supported console remains the Node business CLI.

The release preparer rejects shared layers with the original Node image and verifies matching runtime ledgers across roles. It keeps the existing strict high/critical finding policy. The corresponding-source downloader validates identity/size plus SHA256 against Debian source descriptors, without executing archives; descriptor signatures are not independently verified. Exact source archive contents remain in ignored local candidate evidence and must accompany published artifacts.

## Native finding and required decision

The pinned ARM64 addon SHA256 is `01e2a5ccca7a5cafba293843dc09cda9ca255513489ca92e078bb03b77fb50c0`. Its exported Zstandard version function returns 10507 (1.5.7). Read-only disassembly of `ZSTD_checkContinuity` shows the early return when the output remains contiguous and lacks the history-window bound added by [upstream fix 0c9d297](https://github.com/meta/zstd/commit/0c9d297531a9f15a717ff24604afc0843b3b1427). The [Debian advisory record](https://security-tracker.debian.org/tracker/CVE-2026-124851) covers this release range. This is a native-component blocker even though the filtered OS scan reports no critical/high packages.

[ADR-0010](../../adr/0010-reproducible-kafka-native-build.md) proposes a pinned native source build with patched dependencies, exact component inventories/notices and corresponding sources while preserving client version and application contracts. This build change needs architecture approval under AGENTS.md before implementation. Waiting for a corrected vendor artifact is the alternative. No finding is suppressed on the basis of an internal network alone.

The zlib [upstream discussion](https://github.com/madler/zlib/issues/1310) concerns `gz*` file writes after failures. The ARM64 addon exports `zlibVersion` but inspection found no exported `gzwrite`/`gzclearerr`. Export absence alone is not proof of complete dead-code elimination, so no blanket non-applicability waiver is made. The native source build must establish actual included code and dependency patches.

## Node's bundled dependencies remain a separate scope

All eight final Linux ARM64 runtime ledgers record Node 24.22.3 with bundled Zstandard 1.5.7. Its [pinned upstream source](https://github.com/nodejs/node/blob/v24.22.3/deps/zstd/lib/decompress/zstd_decompress_block.c) also lacks the history-window bound. Bundled [Undici fetch](https://github.com/nodejs/node/blob/v24.22.3/deps/undici/src/lib/web/fetch/index.js) supports Zstandard response decoding, so absence of direct application imports does not prove non-reachability. This is an additional runtime review item; rebuilding the Kafka addon alone does not close it. The owner has not approved a custom Node build, and none is implemented. Prefer a supported upstream fixed runtime; any custom runtime construction needs a separate architecture decision.
